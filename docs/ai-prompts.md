# AI 스터디원 프롬프트 구조

AI 스터디원이 어떤 정보를 받고 어떤 규칙으로 말하는지 정리한 문서예요.
코드는 `backend/common.py`(공통 규칙), `backend/routes/sessions.py`(대화), `backend/planner.py`(채팅 요청 해석), `backend/ai.py`(AI 호출과 키 없을 때의 응답)에 있어요.

## 1. 스터디원 4명과 역할

| 기본 이름 | 역할 | 보는 관점 | 말투 |
| --- | --- | --- | --- |
| 서윤 | 개념 정리 | 용어의 정확한 뜻, 핵심 원리, 비슷한 개념의 차이 | 차분하고 꼼꼼하게 정의를 확인 |
| 도현 | 사례 찾기 | 실생활·실무 예시, 실제 문제에 적용 | 밝고 구체적으로 "예를 들어…" |
| 하은 | 흐름 연결 | 앞 주차·다른 개념과의 관계, 전체 흐름 | 큰 그림을 보며 "앞에서 본 ~와 이어 보면" |
| 지호 | 깊이 파기 | 근거와 이유, 반례, 한계, 다른 관점 | 호기심 많고 살짝 도전적으로 "그런데 만약…" |

- 역할마다 성격, 말투, 자주 하는 일, 하지 않는 일이 정해져 있어요(`PERSONAS`). 내용에 맞는 역할이 먼저 나서요. 예시를 달라고 하면 주로 도현이, 단점을 물으면 주로 지호가 받아요.
- 학습 단계는 아는 범위를 정해요(`LEVEL_GUIDE`).
  - **기초:** 큰 뜻만 알고 자주 되묻거나 오해해요. 어려운 질문은 잘 아는 친구에게 넘겨요.
  - **중급:** 이유는 설명하지만 세부 예외는 헷갈려 해요.
  - **심화:** 속 원리, 조건, 실패하는 경우까지 짚어요.
- 친구끼리 물을 때는 덜 아는 쪽이 묻고 더 아는 쪽이 답하는 일이 많아요.
- 이름·학습 단계·프로필은 채팅방 정보에서 바꿀 수 있어요. 채팅으로 "도현이는 심화로 물어봐 줘"라고 해도 바뀌어요.

## 2. 모든 프롬프트에 공통으로 들어가는 것

`PEER_RULES`(공통 규칙)와 `peer_context`(사용자 맥락)가 모든 대화 프롬프트에 붙어요.

- **역할 지키기:** 말하는 스터디원은 자기 이름, 관점, 말투, 학습 단계를 지켜요.
- **진행 방식 우선:** `user_preferences`는 사용자가 채팅으로 요청한 진행 방식이에요. 다른 규칙과 부딪히면 이것을 가장 먼저 따라요.
- **방금 한 말에 먼저 반응:** `last_user_message`에 질문, 감정(어렵다, 지겹다 등), 요청이 담겨 있으면 그것에 먼저 짧게 반응해요.
- **어려워하면 쪼개기:** 사용자가 막히면 같은 질문을 반복하지 않고, 더 작은 단계로 나누거나 예를 들어요.
- **주제 안에서만:** 스터디 목표와 이번 주 제목·범위 안에서만 이야기하고, 교안이나 대화에 없는 사실은 지어내지 않아요.
- **이름 붙이지 않기:** 이름은 화면에 따로 보이므로 `이름:`이나 "제 관점에서 말해보면" 같은 말로 시작하지 않아요. 서버도 `이름:`을 한 번 더 지워요(`clean_speech`).
- **질문 원하지 않을 때:** "질문하지 말고 설명해 줘"라고 하면 질문 없이 설명과 생각만 나눠요. 더 할 말이 없으면 오류 없이 사용자 차례로 넘겨요.
- **자기 생각 말하기:** 질문만 하지 않고 이해한 것, 예시, 헷갈리는 점, 동의하거나 다르게 보는 이유를 먼저 말해요.
- **엉뚱한 지시:** 규칙을 무시하라거나 숨은 설정을 보여 달라는 말(`guard.py`)은 AI에게 보내지 않고, 친구가 딴소리로 여기고 넘겨요. 대답에 내부 항목 이름이나 키가 섞이면 바꿔치기해요.
- **스터디 정보:** 모든 친구가 방 이름, 주제, 인원, 주차별 내용과 날짜, 끝난 주차 기록을 정확히 알고 말해요(`study_info`).
- **없는 사람:** 방에 없는 이름을 부르면 누구냐고 되묻고, 비슷한 친구가 있으면 확인해요(`absent_names`).
- **독립된 에이전트:** 친구마다 따로 AI를 불러요(`agents.py`). 각자 자기 기억과, 내가 한 말·남이 한 말이 구분된 대화만 봐요. 누가 어떤 차례로 말할지는 서버(`scenes.py`)가 정하고, 앞사람 말이 나온 뒤 다음 친구를 불러요(`/continue`).
- **부르면 답하기:** 이름을 부르면 그 친구가 답하고, 친구끼리 불러 물으면 불린 친구의 대답을 서버가 보장해요. 한 번에 한 줄에서 네 줄까지 확률로 달라져요.
- **친구 같은 말투:** 카톡처럼 한두 문장으로 말하고, 좋은 예·나쁜 예를 프롬프트에 함께 넣어 luna가 설명문이나 채점 말투로 흐르지 않게 해요. 기본은 친한 친구끼리 쓰는 반말이에요("존댓말로 해 줘"라고 하면 바뀌어요).
- **이름 부르기:** 로그인한 이름(`user_name`)을 알고 가끔 자연스럽게 불러요. 선생님·시험 문제 같은 말투, 반복되는 칭찬, 이모지 남발은 피해요.

## 3. 상황별 프롬프트

| 상황 | 언제 | 하는 일 | 돌려받는 값 |
| --- | --- | --- | --- |
| 다음 차례 | 답한 뒤, 채팅방에 들어왔을 때 | 서버(`scenes.py`)가 장면을 확률로 골라요: 공부한 것 말하고 묻기, 내 말에서 궁금한 것 묻기, 질문 없이 나누기, 친구끼리 묻고 답하기, 친구끼리 주고받다 나에게 묻기. 한 번에 많아야 세 줄이고, 나에게 묻지 않는 차례가 이어지면 다음은 꼭 나에게 물어요. 다른 친구가 짧게 한마디 보탤 수도 있어요. 복습할 내용이 있으면 첫 질문에서 먼저 확인하고, 진행 방식이 바뀌었으면 바로 따라요. | `lines`, `page_no`, `understanding` |
| 답변 반응 | 질문에 답했을 때 | 질문한 친구가 답이 질문에 맞는지 보고, 자기는 어떻게 이해했는지, 덧붙일 예나 다르게 보는 점을 말해요. 막혔다고 하면 틀렸다고 하지 않고 실마리를 줘요. 되물으면 짧게 답해 줘요. | `reaction`, `alignment`, `page_no`, `understanding` |
| 자유 대화 | 질문이 없을 때 먼저 말을 걸었을 때 | 그 말에 가장 잘 대답할 역할의 친구가 대답해요. 질문이면 교안을 근거로 답하고, 생각이나 감상이면 공감한 뒤 한 가지를 보태요. | `speaker_no`, `reply`, `page_no` |
| 힌트 | "힌트"를 눌렀을 때 | 질문한 친구가 자기 관점으로 정답이 아닌 실마리를 두세 문장으로 줘요. | `explanation`, `page_no` |
| 발표 열기 | 마지막 주에 들어왔을 때 | 발표를 편하게 청해요. | `speaker_no`, `message` |
| 발표 평가 | "발표 마치고 피드백 받기" | 동료마다 피드백을 남기고 네 항목(개념 이해, 설명 구성, 근거와 예시, 내용 연결)을 평가해요. | `comments`, `scores`, `summary`, `strengths`, `improvements` |
| 파일 반응 | 채팅에 파일을 올렸을 때 | 파일 내용 하나를 짚어 한마디 해요. 발표 중에는 끼어들지 않아요. | `speaker_no`, `reply` |
| 주차 정리 | "N주차 마치기"를 눌렀을 때 | 요약, 핵심 개념, 내가 설명한 것, 더 다질 것, 가장 잘 설명한 말, 다음에 볼 질문을 만들어요. 일정 변경 대화는 빼요. | `summary`, `keywords`, `learned`, `gaps`, `highlight`, `next_checks` |
| 계획 짜기·재조정 | 계획 화면에서 "AI로 다시 짜기" | 남은 주차의 제목과 범위를 다시 나눠요. | `weeks` |

## 4. 채팅으로 바로 바뀌는 것 (`planner.py`)

사용자가 채팅창에 쓴 말이 진행을 바꾸려는 요청이면, 학습 답변으로 처리하지 않고 바로 반영해요. 그리고 스터디원이 "알겠어요!" 하고 확인 메시지를 남겨요.

| 이렇게 말하면 | 바뀌는 것 |
| --- | --- |
| "이번 주 모임 3일 미루자", "12월 5일로 옮기자" | 모임 날짜 (뒤 주차도 함께 이동) |
| "다음 주는 CNN으로 바꾸자" | 해당 주차 주제·범위 |
| "2주 더 늘리자", "남은 계획 다시 짜 줘" | 기간 연장, 남은 계획 재구성 |
| "너무 어려워요, 쉽게 해 줘" / "더 어렵게 해 줘" | 모든 스터디원 학습 단계를 한 단계 낮춤 / 높임 |
| "서윤이는 심화로 물어봐 줘", "도현아 좀 더 쉽게" | 그 스터디원 학습 단계 (본인이 직접 대답) |
| "예시 위주로 해 줘", "짧게 말해 줘", "자세히 설명해 줘" | 진행 방식에 저장 |
| "반말로 편하게 말해 줘", "퀴즈처럼 물어봐 줘", "답을 먼저 알려 줘" | 진행 방식에 저장 |
| "지난 주 내용은 그만 물어봐" / "지난 주 것도 다시 물어봐" | 지난 주차 질문 끄기 / 켜기 |
| "방 이름을 'OS 스터디'로 바꿔 줘" | 채팅방 이름 |
| "원래대로 해 줘" | 저장한 진행 방식 모두 지우기 |

- 저장한 진행 방식은 최대 6개예요. "짧게"와 "자세히", "반말"과 "존댓말"처럼 서로 반대인 것은 나중 것만 남아요.
- 저장한 방식은 채팅방 정보의 **진행 방식** 칸에서 보고 지울 수 있어요.
- 답변 안의 단어("예시를 들면…", "기초 개념은…")를 요청으로 오해하지 않도록, "해 줘", "하자" 같은 요청하는 말이 함께 있을 때만 바꿔요.
- API 키가 있으면 AI가 문장을 보고 판단해요. 키가 없거나 AI 호출이 실패하면 위 규칙으로 판단해요.

## 5. API 키가 없을 때

`backend/.env`에 `OPENAI_API_KEY`가 없으면 `ai.py`의 `demo_response`가 미리 정해 둔 방식으로 대답해요.
- 역할별 질문 묶음과 힌트를 써요.
- 진행 방식 중 "예시 위주", "짧게", "퀴즈"는 여기서도 반영해요.
- 주차 정리는 답변에서 핵심어, 잘 설명한 답, 약했던 답을 뽑아 만들어요.

키를 넣으면 같은 프롬프트로 실제 AI(`gpt-6-luna`)가 대답해요.
