# AI 스터디메이트

학술제 참가신청서의 프로젝트 기획을 구현한 로컬 시연용 Flutter + FastAPI 프로젝트입니다. 
## 실행

Python 3.11 이상과 Flutter SDK가 필요합니다. API 키는 서버의 환경변수 또는 `backend/.env`에만 저장합니다. 앱 화면이나 GitHub에 넣지 않습니다.

```powershell
cd backend
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
uvicorn main:app --reload --host 127.0.0.1 --port 8000
```

실제 AI를 쓰려면 OpenAI Platform에서 프로젝트 API 키를 발급한 뒤 `backend/.env.example`을 `backend/.env`로 복사하고 `OPENAI_API_KEY=` 뒤에 키를 넣으세요. `DEMO_MODE=1`이 설정되어 있다면 해제하고 서버를 재시작하세요. `/health`의 `ai_ready`가 `true`이면 키가 설정된 상태입니다. 이 상태만으로 API 호출 성공이나 결제 설정을 보증하지는 않습니다. `backend/.env`는 Git에서 제외됩니다.

API 키 없이 화면 흐름을 시연하려면 서버 실행 전에 `$env:DEMO_MODE="1"`을 설정하세요. 이 모드의 계획·질문·요약은 규칙 기반 예시이며 생성형 AI 결과가 아닙니다. 체험 모드에서 `ai_ready`는 `false`입니다.

다른 터미널에서:

```powershell
cd flutter_app
flutter create . --platforms web,android
flutter pub get
flutter run -d chrome --dart-define=API_BASE_URL=http://localhost:8000
```

Android 에뮬레이터에서는 `flutter run --dart-define=API_BASE_URL=http://10.0.2.2:8000`을 사용합니다. 포함된 Android manifest는 로컬 시연을 위한 인터넷 권한과 HTTP 연결 설정을 담고 있습니다. 배포할 때는 HTTPS 주소를 사용하세요.

Swagger 문서는 서버를 켠 뒤 `http://127.0.0.1:8000/docs`에서 확인할 수 있습니다.

백엔드 통합 시험은 `backend`에서 `pip install -r requirements-dev.txt` 후 `python -m unittest test_flow.py`로 실행합니다. AI 응답은 시험에서 가짜 응답으로 대체하므로 API 키가 필요하지 않습니다.

## 시연 순서

1. 앱을 열면 고정한 스터디 채팅방으로 바로 들어갑니다. 왼쪽 메뉴에서 다른 방을 선택하거나 시작할 방을 고정할 수 있습니다.
2. 새 방은 주제만 입력해 만들 수 있습니다. 목표·기간·주당 시간·AI 친구 설정과 PDF 교안은 선택사항이며 기본값이 적용됩니다.
3. 채팅방에서 이번 주 범위와 복습 내용을 확인하고 바로 대화합니다. 학습 정리는 선택사항입니다. 교안이 없으면 목표를 기준으로 질문합니다.
4. AI 동료가 먼저 질문합니다. 답변하면 질문과 교안을 참고해 반응한 뒤 다음 질문을 이어 갑니다. 필요하면 힌트를 요청하고, 답하지 못한 질문은 복습으로 표시합니다.
5. 대화를 마치면 추가 정리를 적지 않아도 회의록과 다음 주 복습 항목이 저장되고 다음 주차 채팅으로 이어집니다.

진행 중인 랩미팅은 해당 주차의 **대화 이어하기**에서 다시 열 수 있습니다. 끝난 랩미팅은 스터디 화면의 회의록을 눌러 대화와 요약을 확인할 수 있습니다.

PDF 없이 만들면 핵심 개념·원리와 예시·복습 순서의 기본 계획을 제안합니다. 교안이 있는 스터디에서만 질문에 관련 페이지를 표시합니다.
2주차부터는 **이전 주차 내용도 질문받기**를 켜거나 끌 수 있습니다. 기본값은 켜짐입니다. 끄면 질문 생성에 이번 주차 교안과 대화만 사용하며, 모든 AI 친구가 끝난 주차의 학습 정리를 기억한 상태는 유지됩니다. 다시 켜면 앞 주차의 교안과 완료된 스터디 기록도 질문에 사용할 수 있습니다.
각 주차에서 진행률과 못 공부한 내용을 저장하면 남은 일정 변경안에 반영됩니다. 변경안은 적용 전에 확인할 수 있습니다.

## 코드 구조

| 파일 | 역할 |
| --- | --- |
| `backend/main.py` | HTTP API, PDF 추출, 기본 주간 분배, 질문 순서, 회의록과 다음 주 복습 반영 |
| `backend/ai.py` | 서버에서만 OpenAI Responses API 호출, JSON 결과 처리 |
| `backend/db.py` | SQLite 테이블과 연결 관리 |
| `flutter_app/lib/main.dart` | 생성·계획 확인/수정·발표·질의응답·회의록 화면 |

## 구현 메모

- PDF는 페이지별 텍스트를 SQLite에 저장합니다. 현재 주차 범위에서 발표문과 겹치는 단어가 많은 페이지 최대 3개를 AI 요청에 포함합니다. 질문에 표시되는 쪽수는 이 페이지들 중 하나일 때만 인정합니다.
- 동료마다 질문 관점과 사용자가 정한 초기 수준·이해 상태를 다르게 설정하고, 이전 질문/답변과 동료의 누적 이해 상태를 다음 질문에 전달합니다. AI가 다음 질문자를 고르고, 다른 동료가 필요할 때 짧게 대화에 참여합니다. 질문은 답변 후에만 다음으로 넘어갑니다.
- 교안이 있으면 관련 페이지를 골라 힌트 생성에도 사용합니다. PDF가 없으면 페이지를 표시하지 않습니다.
- 답변 반응은 직전 질문과 관련 교안 부분을 함께 전달해 생성합니다. 교안 근거가 없으면 정답이라고 단정하지 않습니다. 시연 모드는 교안 정답을 판정할 수 없다고 안내하며, 사용자 답변을 그대로 인용해 질문하지 않습니다.
- 최초 발표문, 답변, 재정리한 설명, 회의록을 각각 저장합니다. 사용자가 복습 필요로 표시한 질문과 AI가 제안한 확인 항목은 다음 주로 전달합니다.
- 스캔 이미지 PDF의 OCR, 회원 계정, 여러 기기 동기화, 음성, 실제 사람 초대는 현재 범위에 포함되지 않습니다. 서버는 로컬 단일 사용자 시연용이므로 외부에 공개하려면 인증과 접근 제어가 필요합니다.
- 질문의 정확성과 동료 같은 말투는 AI 출력에 영향을 받습니다. 교안 페이지 표시만으로 답변 내용의 사실성을 보증하지 않으므로 시연에서는 원문과 대조해야 합니다.
